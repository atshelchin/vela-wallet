# Method correction — render-and-screenshot, not read-and-infer

**Date**: 2026-07-29 · **Raised by**: founder · **Status**: adopted, supersedes the original research decisions where they conflict

## The defect

Everything built before this note derived the *visual* spec from **reading React Native source**
(`StyleSheet` objects, token constants, component props) and never from **looking at the running
app**. Token *values* survive that method — they are literal constants and were parity-audited
against `theme.ts`. Everything above the token layer does not: real layout, real proportions,
what a component looks like assembled, which elements even exist on a screen.

Consequence: the Penpot components and boards produced so far do not match what the app renders.

## Evidence gathered within minutes of first running the app (web, parallel space, 390×844)

| What the code-derived spec said | What the app actually renders |
|---|---|
| Home tab row = 3-segment toggle | The third segment is **clipped by the network-filter pill**; the track scrolls to centre the active chip, so neighbours are cut mid-word |
| — (absent from every report) | A **network-filter pill** with overlapping chain logos + "All" + chevron sits inline in the tab row |
| Hero balance = symbol subordinated ~0.58 | The `$` is large; what is subordinated and greyed is the **decimal tail** (`.19`) |
| Receive = Address / Request toggle + QR | Receive opens on a **"Before you receive" safety gate** — warning shield, red-then-green copy, black "I Understand" CTA, and a 12-network logo grid. This whole state was missing from the inventory |
| Send buttons = VelaButton variants | Send has **dashed-outline accent buttons** ("+ Add recipient", "Import list") — a button style that exists in no report |
| Signing sheet ≈ header + body + slide control | Real sheet: dApp identity row (avatar, name, mono domain, chain chip), red intent label, **two-colour headline**, token + SPENDING CAP input with cursor, Custom/Revoke pills, collapsible "Technical details", fee row with refresh affordance, signing-account row, disabled slide control at 45 % accent |

## The corrected method

1. **Render first.** Every screen, every state, every component is screenshotted from the running
   app before any Penpot shape is drawn. Screenshots live in
   `specs/002-penpot-design-source/screenshots/` and are the primary visual authority.
2. **Inventory reports are demoted** from "visual truth" to "behavioural/structural notes and
   source-file index". Where a report and a screenshot disagree, the screenshot wins and the
   report is corrected.
3. **Components get a real gallery.** A dev-only `/design-gallery` route renders every shared
   component in every state, each cell individually addressable, so components are screenshotted
   in isolation rather than inferred. (The app already ships two such galleries —
   `/clear-signing-test` with 27 signing scenarios and `/receipt-harness` — those are captured too.)
4. **Penpot work already produced from inference is treated as a draft to be rebuilt**, not as
   a baseline to patch. Tokens (parity-audited) and the IA/route documentation (derived from the
   router, not from pixels) survive; components and screen boards are rebuilt from screenshots.
5. **Capture caveat to honour**: web renders text at ×1.2 (`WEB_TEXT_BOOST`). Screenshots are
   authoritative for *layout, composition, colour and what exists*; exact type sizes come from the
   tokens (divide the web-rendered size by 1.2 to recover the base).

## Impact on the plan

- `research.md` R7 (verification) is extended: visual verification is no longer a final spot-check,
  it is the *input* to every board.
- `tasks.md` US2/US4 are re-scoped: build from `screenshots/`, with the manifest still supplying
  the required board/state list.
- The rebuild-readiness gate (US5) gains a concrete acceptance test: a board and its source
  screenshot placed side by side must not disagree on any element that exists.
