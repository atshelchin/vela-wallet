# Data Model: Identicons in the shared Rust core

**Date**: 2026-07-30 · **Phase**: 1 · Entities from [spec.md Key Entities](./spec.md#key-entities),
refined by research decisions D3–D9. Rust is the source of truth; Kotlin/Swift shapes
are generated by uniffi and TS shapes derived by tsify. `app-desktop` uses the Rust
types directly with no marshalling.

## Conventions

- **Colours** are 7-character uppercase hex strings including `#` (`"#FC8702"`),
  exactly as the JS library emits them into SVG. They are `&'static str` inside the
  core — every possible value is a compile-time constant — and `String` over FFI.
- **Section artwork** is likewise `&'static str` inside the core: an SVG fragment,
  not a file path, not an index.
- **Every fallible function** returns `Result<T, CoreError>`. No function returns a
  default value, a placeholder colour, or a blank identicon on bad input (FR-004);
  the one exception is `create_identicon`, where returning the library's placeholder
  *is* the specified behaviour for an address that fails validation.
- **Nothing is mutable and nothing is cached** (FR-008). Every type below is
  `Copy` or borrowed from `.rodata`.

## Seed

Not a distinct Rust type — a `&str` — but it carries rules, because the seed is what
determines the avatar and therefore what must match across platforms.

| Property | Value |
|---|---|
| Accepted | any valid UTF-8 string, including empty |
| Normalisation (Vela policy, D9) | full Unicode lowercase, then truncate to 128 UTF-16 code units (that order — lowercasing can change length) |
| Normalisation return | `Cow<'_, str>` — borrowed when already normalised (the common case) |
| Rejected | nothing at this layer; degenerate seeds are rejected downstream by `identicon_params` |
| Vela's actual domain | 42-character `0x`-prefixed hex addresses |

Callers on every platform MUST route through `normalize_seed` rather than
lowercasing themselves, or the four platforms can disagree for the same account.

## IdenticonHash

The decimal digit string every downstream choice indexes into.

```rust
pub struct IdenticonHash { buf: [u8; 17], len: u8 }   // Copy, no allocation
impl IdenticonHash {
    pub fn as_str(&self) -> &str;
    pub fn is_degenerate(&self) -> bool;   // true iff a non-digit is present
}
// + Display, PartialEq<str>, Debug
```

| Property | Value | Source |
|---|---|---|
| Length | 13–17 bytes | measured distribution: 13:5,361 · 14:3,504 · 15:20,677 · 16:35,996 · 17:134,488 (research D5) |
| Alphabet, normal | `0`–`9` | — |
| Alphabet, degenerate | `e` at index 0 only; `.` possible in Regime B | research D5 |
| Max length is 17 because | `slice(4, 21)` caps it, and `acc ∈ (0, 0.5]` bounds the decimal form | research D7 |

The fixed 17-byte inline buffer is what makes `make_hash` allocation-free, and the
17-byte bound is a proved consequence of the value domain, not an assumption.

## Colors

```rust
pub struct Colors {                    // Copy
    pub main: &'static str,
    pub background: &'static str,
    pub accent: &'static str,
}
```

Drawn from two 10-entry palettes that differ only at indices 3 and 5:

| Index | `COLORS` (main, accent) | `BACKGROUND_COLORS` (background) |
|---|---|---|
| 0 | `#FC8702` | `#FC8702` |
| 1 | `#D94432` | `#D94432` |
| 2 | `#E9B213` | `#E9B213` |
| **3** | **`#1A5493`** | **`#1F2348`** |
| 4 | `#0582CA` | `#0582CA` |
| **5** | **`#5961A8`** | **`#5F4B8B`** |
| 6 | `#21BCA5` | `#21BCA5` |
| 7 | `#FA7268` | `#FA7268` |
| 8 | `#88B04B` | `#88B04B` |
| 9 | `#795548` | `#795548` |

**Selection rules** (order matters — this is the upstream `colorsToRgb`):

1. `main = hash[0]`, `background = hash[2]`, `accent = hash[11]`, as single digits.
2. If `main == background`, then `main = (main + 1) % 10` — applied **once**, not in a loop.
3. While `accent == main || accent == background`, `accent = (accent + 1) % 10`.
4. Look `main`/`accent` up in `COLORS`, `background` in `BACKGROUND_COLORS`.

Step 2 comparing *indices* while step 4 reads *different palettes* means `main` and
`background` can still resolve to the same hex string (index 3 vs 3 is excluded by
step 2, but the palettes differ there anyway). That is upstream behaviour and is
preserved.

In JS-compat mode (FR-005), `main` may be the literal `"undefined"` — the string V8
produces from `colors[NaN]`.

## Sections

```rust
pub enum Section { Face, Sides, Top, Bottom }   // Copy

pub struct Sections {                            // Copy
    pub top: &'static str,
    pub sides: &'static str,
    pub face: &'static str,
    pub bottom: &'static str,
}
```

| Property | Value |
|---|---|
| Artwork per section | 21 fragments, addressed `1..=21` |
| Total artwork | 84 fragments, 82,955 bytes, largest 2,707 bytes (measured) |
| Index derivation | `face = hash[3..5]`, `top = hash[5..7]`, `sides = hash[7..9]`, `bottom = hash[9..11]`, each parsed as a 2-digit number |
| Index → artwork | `abs(n % 21) + 1` |

**`hash[5]` is read twice** — as the low digit of `face` and the high digit of
`top`. That is upstream behaviour; a "cleanup" that gave each section disjoint digits
would change every avatar.

## IdenticonParams

```rust
pub struct IdenticonParams { pub colors: Colors, pub sections: Sections }  // Copy
```

The complete description of an identicon, independent of how it is drawn. 56 bytes of
pointers, no heap. `assemble_svg` and `assemble_svg_circular` are pure functions of
this value, which is what lets one params computation serve both the stock hexagonal
and the wallet's circular rendering.

## Shared SVG fragments

Verbatim constants from the library, exposed so callers can assemble custom layouts
the way `Identicon.tsx` does today:

| Constant | Role |
|---|---|
| `DEFAULT_SHADOW` | inner shadow path, `opacity=".1"` |
| `DEFAULT_BACKGROUND_SHAPE` | the hexagon used as `clipPath` in stock output |
| `IDENTICON_PLACEHOLDER` | 64×64 grey hexagon returned for an invalid address |
| `IDENTICON_PLACEHOLDER_BASE64` | the same, pre-encoded as a data URI |
| `default_circle_shape(color)` | `<circle cx="80" cy="80" r="40" fill="{color}"/>` |

## CoreError extension

One new variant on the existing flat `CoreError` (data-model conventions of feature
001 apply unchanged: variants classify, messages carry detail):

| Variant | Code | Raised by |
|---|---|---|
| `InvalidIdenticonSeed(String)` | `InvalidIdenticonSeed` | a seed whose chaotic hash lands in Regime A (`hash[0] == 'e'`, three-digit exponent — strict mode only) or Regime B (non-digit section indices, where JS itself throws — both modes) |

The message names the regime and quotes the offending hash, so a report of "my avatar
is missing" is diagnosable from a log line rather than needing a repro.

**Foreign mapping** follows the established pattern automatically: the uniffi shell
needs the mirror variant added to its `CoreError` enum and `From` impl; the wasm shell
needs nothing, because it serialises `e.code()` generically.

## Invariants (asserted by tests, not just documented)

1. `acc ∈ (0, 0.5]` for every input — strictly decreasing, since `max(chaos) = 0.8924891966912822 < 1`.
2. `IdenticonHash::as_str().len() ∈ 13..=17`.
3. Every section index resolves into `1..=21`.
4. The three colours are pairwise distinct **as indices** after selection.
5. `make_hash` performs zero heap allocations; `identicon_svg` performs exactly one.
6. No input of any kind panics (property-tested).
7. The compile-time chaos table equals the runtime loop, bit for bit, for all 131 entries.
