# Data Model: i18n / L10n in the shared Rust core

**Date**: 2026-07-31 · **Phase**: 1 · Entities from [spec.md Key Entities](./spec.md#key-entities),
refined by research decisions D1–D6. Rust is the source of truth; Kotlin/Swift shapes
are generated by uniffi and TS shapes derived by tsify. `app-desktop` uses the Rust
types directly with no marshalling.

Every number below is either measured (source named inline) or arithmetic over a
measured number. Nothing here is estimated.

## Conventions

- **The oracle is `i18next@26.3.1` in MODE A** (full `Intl.PluralRules`). Line
  citations are into `node_modules/i18next/dist/esm/i18next.js` at that version.
  Where this document says "i18next does X", it was read there and replayed.
- **Catalog strings are borrowed, never copied.** A resolved value is `&str` tied
  to the catalog's lifetime; only interpolation allocates, and only when the
  template actually contains a placeholder.
- **Every fallible function returns `Result<T, CoreError>`** (feature 001's FR-004,
  standing). Where i18next returns a diagnostic *string* rather than throwing, the
  core returns that exact string as `Ok` — the diagnostic is data, not an error.
- **Nothing in the engine is mutable except the registry.** No per-key cache, no
  memoised suffix table, no interned-options map (FR-024). The plural resolver is a
  `fn` pointer; i18next's `pluralRulesCache` has no analogue and needs none.
- **Sizes** are bytes. "wasm32" means the `wasm32-unknown-unknown` target as built
  by `rust/scripts/build-web.mjs`; "64-bit" means a native `aarch64`/`x86_64`
  build. Pointer width changes slice sizes, so both are given where they differ.

## Catalog

One locale's values, addressed by a **shared** path table that all locales use.
The split is the whole of decision D2: key bytes repeated per locale cost 460,471
bytes, interned once they cost 31,198 — a 14.8× collapse
(`catalog_proto/gen/stats.json`).

### The shared path table (compiled in once, never released)

```rust
/// GENERATED — src/i18n/paths.rs. Sorted, deduplicated, identical for every locale.
pub static PATHS: &[&'static str];      // 1,205 entries
pub static IS_BRANCH: &[u8];            // 151 bytes, bit i = PATHS[i] is an object node
pub const N_PATHS: usize = 1_205;
```

| Property | Value | Source |
|---|---|---|
| Total paths | **1,205** = 1,141 leaf + 64 branch | re-derived over all 240 files |
| Leaf paths per locale | en 1,129 · zh 1,129 · ru 1,131 · the other twelve 1,119 | `stats.json` |
| Sum of per-locale leaves | 16,817 | `stats.json` |
| Leaf depth | 2 (499 paths) or 3 (642 paths) — maximum depth **3** | measured |
| Branch depth | 1 (22 paths) or 2 (42 paths) | measured |
| Path length | 4–49 bytes | measured |
| Path charset | `[0-9A-Za-z_]` plus the `.` separator; minimum segment byte is `0x30` (`'0'`), **above** `0x2E` (`.`), so byte order and path order agree | measured |
| Paths that are both leaf and branch | **0** | measured |
| Literal-dot keys in the JSON | **0** across all 240 files | D2 |
| Key blob | 32,173 bytes (31,198 for leaves alone, +975 for branch paths) | `stats.json` |
| `PATHS` slice itself | 1,205 × 8 = **9,640** bytes (wasm32) · × 16 = **19,280** (64-bit) | fat pointers |
| Branch bitmap | ceil(1205 / 8) = **151** bytes | — |
| **Shared total** | **41,964** (wasm32) · **51,604** (64-bit) | 32,173 + slice + 151 |

**Branch nodes are first-class entries**, not a derived prefix probe. A branch must
be reported even when the *active* locale has none of its children — which a
per-locale successor probe cannot see, and which is exactly the `t("home")` case.
The bitmap costs 0.1% of the SC-005 budget and makes the test O(1). (D2 measured
the successor probe at 29.0 ns and correct only for a per-locale table.)

### Per-locale values (loaded on demand, released on demand)

```rust
/// One locale's values. `Static` = compiled in behind a cargo feature (FR-014);
/// `Owned` = parsed from host JSON at runtime (FR-015). Both index the SAME
/// shared `PATHS` ids, so the resolver has one code path and release is a Drop.
pub enum Values {
    Static {
        blob:    &'static str,
        off:     &'static [u16],   // N_PATHS + 1 = 1,206 entries
        present: &'static [u8],    // 151 bytes
    },
    Owned(OwnedValues),
}

pub struct OwnedValues {
    blob:    Box<str>,
    off:     Box<[u16]>,
    present: Box<[u8]>,
    branch:  Box<[u8]>,                     // this catalog's OWN branch bitmap
    extra:   Box<[(Box<str>, Box<str>)]>,   // sorted; paths absent from PATHS
}

pub struct Catalog {
    pub lang:   LangTag,      // normalised, inline, Copy
    pub values: Values,
    pub plural: PluralRule,   // fn(f64) -> PluralCategory
    pub dir:    Dir,          // Ltr | Rtl
}

#[derive(Clone, Copy, PartialEq, Eq)]
pub struct LangTag([u8; 8], u8);   // no heap; longest shipped tag is 5 bytes

pub enum Dir { Ltr, Rtl }

pub enum Lookup<'a> { Value(&'a str), Branch, Missing }
```

Three corrections to `catalog_proto/src/api_sketch.rs`, which was written to
*measure*, not to ship:

1. **`off` is `u16`, not `u32`.** Every locale's value blob is under 64 KiB — the
   largest, `ru`, is 57,701 bytes, leaving 7,835 bytes of headroom. u32 offsets put
   the 64-bit ja+en total at 135,992, which is **647 bytes over** SC-005's 135,345
   budget; u16 brings it to **131,168** on every pointer width (D2). The generator
   MUST assert `blob.len() < 65_536` per locale and fail loudly rather than
   silently truncate.
2. **`Owned` carries its own `branch` bitmap.** The prototype reuses the
   compiled-in `IS_BRANCH`, which is wrong for a runtime-loaded locale whose object
   structure need not match the shipped corpus. Recorded as a known gap in D2 and
   in plan.md's risk list; closed here by making it a field.
3. **`Owned` carries an `extra` overflow list.** A runtime catalog may contain
   paths that are not in the compiled-in `PATHS`. They are sorted and binary
   searched after the shared table misses, so an unknown-to-the-binary locale still
   resolves. `Static` has no `extra` — by construction every path it holds is in
   `PATHS`.

### Lookup

One binary search over the shared table, then an O(1) index:

```
path_id = PATHS.binary_search(key)           -> Err  => Missing
present[path_id]                             -> true => Value(&blob[off[i]..off[i+1]])
IS_BRANCH[path_id] (Static) / branch[..] (Owned)
                                             -> true => Branch
otherwise                                    => Missing
```

Measured at **21.1 ns** with **0 allocations** (D2). `Branch` is a distinct outcome
so the caller can emit the byte-exact diagnostic (see CoreError, below).

### Flattening is behaviour-preserving, and it was proved

The nested JSON becomes a flat path table only because the corpus permits it:
1,129/1,129 `en` leaves resolve to the flattened value under the live oracle; 0
literal-dot keys exist; 0 paths are both leaf and branch. For inputs *outside* the
corpus — dApp-supplied text reaching `t()` as a key — the resolver must still apply
i18next's `deepFind` precedence (shortest defined prefix wins; a nested `zz.yy.xx`
beats a flat `"yy.xx"` child), which the `extra` list and the branch bitmap
together preserve.

## CatalogRegistry

```rust
pub struct CatalogRegistry {
    en:     Catalog,           // pinned: a field, not a slot
    active: Option<Catalog>,   // at most one non-`en` locale, ever
}
```

Residency is **structural**, not policed at runtime. `en` is a field, so FR-013's
"the `en` fallback is pinned" cannot be violated. `active` is a single `Option`, so
FR-012's "one locale at a time" has nowhere to leak: loading a second locale
`replace`s the first, and the old catalog drops at that point.

| Operation | Signature | Behaviour |
|---|---|---|
| Cold start | `new(en: Catalog) -> Self` | `active = None`. Never fails, never allocates. |
| Load (FR-012) | `load(&mut self, cat: Catalog) -> Option<Catalog>` | Replaces `active`; returns the displaced catalog so the caller can observe the drop. |
| Load from JSON (FR-015) | `from_json(lang, bytes, plural, dir) -> Result<Catalog, CoreError>` | Flattens, interns against `PATHS`, builds its own branch bitmap and `extra` list. |
| Release (FR-013) | `release(&mut self, lang: LangTag) -> Option<Catalog>` | `Some` iff `lang` is the active one. Releasing `en` is not expressible. |
| Residency query | `resident(&self) -> [Option<LangTag>; 2]` | For the SC-005 measurement and for tests. |

**FR-016 — resolution against a locale that is not resident.** Defined, tested, and
never a panic or a partial read: the lookup falls through to the pinned `en`
catalog, which is exactly what the `[active, "en"]` resolve hierarchy already does
for a key the active locale lacks. Concretely:

| State | `t(key)` behaviour |
|---|---|
| `active == Some(lang)` and the key resolves there | that locale's value |
| `active == Some(lang)`, key missing there | `en` value, or `Missing` handling |
| `active == None` (nothing loaded yet) | `en` value — identical to the previous row |
| `active == Some(other)` (a switch is mid-flight) | `en` value; **never** the other locale's string |

The last row is the one that matters: a race between a render and a catalog load
must not render a *third* language. Because `resolve` compares `c.lang == lang`
before reading, a stale active catalog is skipped rather than read.

Loading is where errors live, not resolving. A locale that is neither compiled in
nor supplied as JSON yields `CoreError::I18nCatalogUnavailable`; malformed JSON
yields `CoreError::I18nCatalogParse`. Neither is reachable from `t()`.

## KeyPath and candidate keys

A **key path** is a `.`-separated path into the nested JSON, optionally prefixed by
a namespace and `:`. The app uses one namespace, `translation`, and never writes
the prefix.

### Separators (i18next defaults, unchanged by the app's init)

| Separator | Value | Source |
|---|---|---|
| `keySeparator` | `"."` | i18next.js:1666 |
| `nsSeparator` | `":"` | i18next.js:1667 |
| `pluralSeparator` | `"_"` | i18next.js:1668 |
| `contextSeparator` | `"_"` | i18next.js:1669 |
| Namespace | `["translation"]`, default `"translation"` | i18next.js:1658-1659 |

`pluralSeparator` and `contextSeparator` are the **same character**, which is why
`key_male_other` is ambiguous on inspection but unambiguous in construction: the
context is appended first, the plural suffix second.

### Candidate construction and the LIFO try order

i18next **pushes** candidates onto `finalKeys` (i18next.js:823-852) and **pops**
them (i18next.js:854-860). The try order is therefore the reverse of the source
order. This is the single most load-bearing undocumented behaviour in the port.

Push order (source order):

| # | Candidate | Emitted when |
|---|---|---|
| 1 | `key` | always — seeded as `finalKeys = [key]` |
| 2 | `key + pluralSuffix` | `needsPluralHandling` |
| 3 | `key + "_zero"` | `needsZeroSuffixLookup` |
| 4 | `key + "_" + context` | `needsContextHandling` |
| 5 | `key + "_" + context + pluralSuffix` | context **and** plural |
| 6 | `key + "_" + context + "_zero"` | context **and** zero |

Pop order — **the actual try order**:

```
key_ctx_zero  ->  key_ctx_plural  ->  key_ctx  ->  key_zero  ->  key_plural  ->  key
```

| Suffix source | Where it comes from |
|---|---|
| `_ctx` | `contextSeparator` + `opt.context`, only if `context !== undefined`, is a string or number, and is not `""` (i18next.js:811) |
| `_plural` | `pluralSeparator` + the CLDR category for `(code, count)`, **recomputed per fallback language code** (i18next.js:828) |
| `_zero` | `pluralSeparator + "zero"`, added only when `count === 0 && !ordinal` (i18next.js:602, 810). **Not a CLDR category** — an i18next extra, tried *first* |

**The bare key is a last resort**, reached only after the plural-suffixed lookup
misses. That is the only reason the 11 corpus keys per locale that interpolate
`{{count}}` without plural siblings (defect A5, 165 entries) render at all. A port
that tries the bare key first breaks 165 strings; a port that omits it breaks the
same 165.

**`needsPluralHandling` is `opt.count !== undefined && !isString(opt.count)`**
(i18next.js:809). A `count` passed as a **string** produces no plural candidate at
all, so `t('send.recipientCount', {count: '3'})` returns the raw key — reproduced,
not repaired.

| `"bogus:common.cancel"` | `"common.cancel"` (unknown ns; the key echoes without the prefix) | `ns/bogus-prefix` |

## ResolveHierarchy

The ordered language codes tried for one lookup.

```rust
pub struct ResolveHierarchy {
    pub language:          LangTag,          // the normalised active code
    pub resolved_language: LangTag,
    pub languages:         Vec<LangTag>,     // 1 or 2 entries under this config
}
```

Under the app's `load: 'currentOnly'` + `supportedLngs` + `fallbackLng: 'en'`
(`src/i18n/index.ts:131-139`), `toResolveHierarchy` (i18next.js:997-1019) collapses
to exactly two shapes:

| Active | `languages` |
|---|---|
| `en` | `["en"]` |
| anything else supported | `[active, "en"]` |

`load: 'currentOnly'` suppresses both the script-part and language-part codes
(i18next.js:1010-1011). **`zh-TW` therefore never reads `zh`**: a key present in
`zh` but absent from `zh-TW` resolves to the **English** value, skipping Simplified
entirely.

### Language-code normalisation — and the asymmetry

**`changeLanguage(lng)` and `t(key, {lng})` are different functions.** The first
routes through `getBestMatchFromCodes` (i18next.js:957-982), which has a
script-part → language-part → prefix-match recovery ladder. The second routes
straight through `toResolveHierarchy`, which only calls `formatLanguageCode` and
then rejects anything not in `supportedLngs`. There is no recovery ladder on the
per-call path.

Measured over the oracle (`out/i18n-behaviour.json`, 17 requested codes × 3
functions = 51 cases):

| Requested | `changeLanguage` / init → `language` | `t(k, {lng})` renders |
|---|---|---|
| `en` | `en` | English |
| `EN` | `en` | English |
| `de` | `de` | German |
| `DE` | **`en`** | English |
| `De` | **`en`** | English |
| `zh` | `zh` | Simplified |
| `ZH` | **`en`** | English |
| `Zh` | **`en`** | English |
| `zh-TW` | `zh-TW` | Traditional |
| `zh-tw` | `zh-TW` | Traditional |
| `ZH-TW` | `zh-TW` | Traditional |
| `ZH-tw` | `zh-TW` | Traditional |
| `zH-Tw` | `zh-TW` | Traditional |
| `zh_TW` | **`zh`** | **English** |
| `zh-Hant` | **`zh`** | **English** |
| `zh-Hant-TW` | **`zh`** | **English** |
| `es-AR` | **`es-MX`** | **English** |

Three mechanisms explain every row, and the port must implement all three:

1. **`formatLanguageCode` only canonicalises codes containing `-`**
   (i18next.js:932-950). It calls `Intl.getCanonicalLocales`, which fixes case
   (`ZH-tw` → `zh-TW`). A code with no `-` is returned **unchanged**, so bare `ZH`
   stays `ZH`, fails `supportedLngs`, and falls to `en`. Uppercasing a regional tag
   is survivable; uppercasing a bare language tag is not.
2. **`getCleanedCode` maps `_` → `-` (i18next.js:191), but only inside
   `getScriptPartFromCode` / `getLanguagePartFromCode`, never in
   `formatLanguageCode`.** So `zh_TW` is invisible to canonicalisation, is rejected
   as unsupported, and survives only through `changeLanguage`'s language-part
   recovery — which yields `zh`. **Traditional silently becomes Simplified.**
3. **`getScriptPartFromCode` returns `null` for a two-part tag**
   (i18next.js:919-927), so `zh-Hant` never resolves via its script; only its
   language part, `zh`, is reachable. `es-AR` reaches `es-MX` through the final
   prefix scan over `supportedLngs` (i18next.js:970-977).

The Rust `resolve_language` reproduces `changeLanguage`; `translate_with_lng_option`
reproduces the per-call path. They are separate entry points precisely because they
are separate functions upstream (D4).

## PluralCategory

```rust
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum PluralCategory { Zero, One, Two, Few, Many, Other }

impl PluralCategory {
    pub fn suffix(self) -> &'static str;   // "_zero" .. "_other"
    pub fn as_str(self) -> &'static str;   // "zero"  .. "other"
}

pub type PluralRule = fn(count: f64) -> PluralCategory;
```

`Zero` and `Two` are **never produced** by any of the 15 shipped locales. They exist
so the enum is the CLDR enum rather than a Vela subset, and so a sixteenth locale
does not change the type. There are 0 `_zero` keys in the corpus (D1).

### The five rule bodies

15 locales collapse to exactly **5** distinct CLDR cardinal rules — and only
**4** distinct category *sets*, because it/es-MX and fr/pt-BR disagree only at
count 0.

| Rule body | Locales | Categories | Predicate |
|---|---|---|---|
| `Other` | zh, zh-TW, zh-HK, ja, ko, vi, id | `[other]` | — |
| `OneOther` | en, de, tr | `[one, other]` | `one` ⟺ *i*=1 ∧ *v*=0 (tr: *n*=1, identical under an f64 API) |
| `OneManyOther` | it, es-MX | `[one, many, other]` | `one` ⟺ *i*=1 ∧ *v*=0; `many` ⟺ *i*≠0 ∧ *i* mod 10⁶ = 0 ∧ *v*=0 |
| `OneZeroToOneManyOther` | fr, pt-BR | `[one, many, other]` | `one` ⟺ *i* ∈ {0, 1}; `many` as above |
| `Russian` | ru | `[one, few, many, other]` | *v*≠0 ⇒ `other`; `one` ⟺ *i* mod 10 = 1 ∧ *i* mod 100 ≠ 11; `few` ⟺ *i* mod 10 ∈ 2..4 ∧ *i* mod 100 ∉ 12..14; else `many` |

Unknown locale ⇒ `OneOther`, matching i18next's fall-through to `dev` == `en`.

The suffix *lists* the engine reports (`plural_suffixes`) are CLDR-ordered
(`zero, one, two, few, many, other` — i18next.js:1022-1029) and were pinned against
the oracle:

| Categories | Locales | Suffix list |
|---|---|---|
| 1 | zh, zh-TW, zh-HK, ja, ko, vi, id | `["_other"]` |
| 2 | en, de, tr | `["_one", "_other"]` |
| 3 | fr, it, es-MX, pt-BR | `["_one", "_many", "_other"]` |
| 4 | ru | `["_one", "_few", "_many", "_other"]` |

**29 reachable (locale, category) pairs**: 7×1 + 3×2 + 4×3 + 1×4. All 29 are
exercised by the D1 cross-validation and by the 825-case MODE A suite (675 `t`
cases, 135 `plural_suffix`, 15 `plural_suffixes`).

### Operands, and the ×1000 scaling rule

Across all 15 locales only three predicates are referenced: *i*, *v*=0 and *n*=1.
`f`, `t`, `w` and the compact exponent `c`/`e` are never referenced and are not
computed.

**`v` is a property of the rendered string, not of the number.**
`Intl.PluralRules` renders with `maximumFractionDigits: 3` and
`roundingMode: "halfExpand"`, stripping trailing zeros. The operand extraction
reproduces exactly that, in integer arithmetic:

```
if !count.is_finite()      -> (i = u64::MAX, v0 = false)   // NaN/±Inf -> Other everywhere
n = |count|
if n < 1e12:
    s  = round(n * 1000.0) as u64        // scale the WHOLE value, half away from zero
    i  = s / 1000
    v0 = (s % 1000 == 0)
else:
    i  = n as u64
    v0 = (n == n.trunc())
```

Three constraints this encodes, each of which was measured:

- **Scale the whole value, never the fraction.** `i = n.trunc()` then
  `round((n - i) * 1000)` produces **6 disagreements** out of 15,810, all at
  `count = 1.0005` in en/tr/ru/es-MX/it/de: `(1.0005 - 1.0) * 1000.0` is
  `0.49999999999994` and rounds to *v*=0, while ICU renders `"1.001"` (*v*=3).
  `1.0005 * 1000.0` is exactly `1000.5` and rounds up, matching.
- **The `is_finite` guard is load-bearing.** `f64 as u64` saturates, so `NaN` would
  otherwise become *i*=0 and select `one` under the fr/pt rule.
- **Operands are `u64`, not `f64`.** wasm has no `f64.rem`; every `%` calls
  `compiler_builtins`' `fmod`, dragging in `__udivti3`/`__multi3`. Carrying
  operands as `u64` took the stripped prototype from 4,230 to 1,295 bytes with
  identical results.
- **The primary subtag is taken with `split`, never `&locale[..i]`.** Range-slicing
  a `&str` emits a UTF-8 boundary check whose failure path links `core::fmt` and the
  panic formatter: **+28,553 wasm bytes** measured.

Validation: **182,790 / 182,790 agreements, 0 disagreements** against the node
full-ICU oracle (15,810 primary cases + 166,980 fuzz cases). wasm cost of the whole
table: **1,204 bytes** (530,780 → 531,984), against `icu_plurals` at 57,960.

### Legacy mode (`dummyRule`, FR-007)

```rust
pub fn plural_suffix_legacy(count: f64) -> &'static str;   // "_one" iff count == 1.0
pub fn plural_suffixes_legacy() -> &[&'static str];        // ["_one", "_other"]
```

Reproduces i18next.js:1030-1035 exactly — `count === 1 ? 'one' : 'other'`, with a
fixed `pluralCategories: ['one', 'other']` for **every** locale. This is what
Hermes gets today, because it ships `Intl` without `PluralRules` and i18next's
`try` at i18next.js:1057-1066 swallows the `TypeError`.

It is not redundant with MODE A: **75 of 825** plural cases differ. The seven
`other`-only locales gain a spurious `_one` and select it at count 1; tr, es-MX,
pt-BR, fr, ru and it lose their `_few`/`_many` categories. `count == 1.0`
in Rust matches JS `count === 1` for every f64, including `-0.0` (which compares
equal to `0.0`, not to `1.0`) and `NaN` (never equal).

### Documented divergence

Exact for `|count| < 1e18`. At or above 1e18 ICU switches to a scientific
representation (*i*=1, *e*=18) and returns `other` for `it` / `one` for `fr`, where
the literal CLDR rule text computes `many`. `5e17` still agrees. No wallet count
reaches 1e18; recorded rather than fixed, and encoded as a divergence entry rather
than as a passing vector.

### Value coercion

Two distinct paths produce visibly different results, and conflating them is the
easiest way to get this wrong (i18next.js:1207-1222):

| Value | Renders as | Path |
|---|---|---|
| **absent** (not an own property) | the literal `{{v}}` | `skipOnVariables: true` (i18next.js:1711) |
| own property, `undefined` | `""` | `hasOwnProperty` branch, i18next.js:1211-1212 |
| `null` | `""` | `makeString`: `object == null` ⇒ `''` (i18next.js:13-16) |
| `0` | `"0"` | `String(0)` |
| `-0` | `"0"` | `String(-0)` is `"0"`, not `"-0"` |
| `false` / `true` | `"false"` / `"true"` | — |
| `NaN` | `"NaN"` | — |
| `Infinity` / `-Infinity` | `"Infinity"` / `"-Infinity"` | — |
| `1234.5` | `"1234.5"` | JS number-to-string, **not** locale formatting |
| `1e21` | `"1e+21"` | JS switches to exponential at ≥1e21 |
| bigint `123456789012345678901234567890` | the full decimal digits | — |
| `""` | `""` | — |
| `"{{v}}"` | `"{{v}}"` — not re-scanned | `lastIndex` arithmetic, i18next.js:1225-1228 |
| `{a: 1}` | `"[object Object]"` | — |
| `[1,2,3]` | `"1,2,3"` | `Array.prototype.toString` |
| `[[1],[2]]` | `"1,2"` | flattening join |
| `Date` | `Date.prototype.toString()` | **divergence** — reads the ambient TZ; unrepresentable |
| function | its **source text** | **divergence** — a latent source leak in TS; rejected in Rust |
| object with custom `toString` | that method's return | **divergence** — no dynamic dispatch in Rust |

`count` follows the *same* coercion when it is interpolated, but a different rule
for plural selection: `null` still interpolates as `""` while selecting `other`
(`" recipients"`); an own-property `undefined` disables plural handling entirely
and yields the raw key; a string disables it too; a bigint **throws** in
`Intl.PluralRules.select`.

### Forms, escaping and replacement

| Property | Value |
|---|---|
| Prefix / suffix | `{{` / `}}` (i18next.js:1139-1140) |
| Unescape form | `{{- var}}`; the unescape pass runs **first** (i18next.js:1195-1201) |
| Pattern | `\{\{(.+?)\}\}` — non-greedy, non-backtracking; a hand-rolled scanner is exact here |
| Variable name | `match[1].trim()`, so `{{ v }}` == `{{v}}` |

| Replacement | `str.replace(match[0], safeValue)` — **first occurrence**, not splice-at-index |
| `maxReplaces` | 1,000 (i18next.js:1710) |

### Nesting (`$t(...)`, FR-003)

Prefix `$t(`, suffix `)` (i18next.js:1144-1145); options separator `,`. A missing
target renders as the bare key (`A $t(zz.nope) B` → `A zz.nope B`); a
self-reference is broken at depth 1 and renders as the key (`S $t(zz.self) E` →
`S zz.self E`); a malformed call is left verbatim (`A $t(common.cancel B`).
Inherited options are merged, and `$t(send.recipientCount, {"count": 5})` selects
the plural in the nested call. Nesting resolves against the **active** locale, so
`$t(common.cancel)` under `zh` yields `取消`.

No corpus value contains `$t(` (D6). Nesting's only live consumer is dApp-supplied
text reaching `t()` as a key — see research.md open question 2.

### `defaultValue` precedence

`needsZeroSuffixLookup && defaultValue_zero` ‖ `defaultValue<suffix>` ‖
`defaultValue<ordinalFallbackSuffix>` ‖ `defaultValue` (i18next.js:603). The
suffix comes from the **active** language, not from each fallback code. A found
translation always wins over any default.

| Case | Result |
|---|---|
| `defaultValue: "D"` on a missing key | `"D"` |
| `defaultValue: null` | ignored ⇒ the key echoes |
| `defaultValue: ""` | **honoured** ⇒ `""` |
| own-property `undefined` | ignored ⇒ the key echoes |
| `defaultValue: 42` / `true` | `"42"` / `"true"` — i18next returns the raw number/boolean; Rust returns `String` (divergence, recorded) |
| `defaultValue: {…}` or `[…]` | the branch diagnostic string |
| `count: 1`, both `defaultValue` and `defaultValue_other` | `defaultValue` wins (the *one* suffix has no entry) |
| `count: 5`, `lng: ru`, full suffix set | `defaultValue_many` |
| `count: 0`, `defaultValue_zero` + `defaultValue_other` | `defaultValue_zero` |

## Format presets

Read from `src/services/locale-format.ts`. Each family has an `auto` variant
resolved from the device (`Intl.*.formatToParts` when available, else the
documented default); `auto` is memoised per process.

### 4 number presets (`NUMBER_STYLES`, locale-format.ts:33-38)

| Key | Group | Decimal | Indian 2-3 |
|---|---|---|---|
| `comma_dot` | `,` U+002C | `.` U+002E | no |
| `dot_comma` | `.` U+002E | `,` U+002C | no |
| `space_comma` | U+0020 — a **plain ASCII space**, not NBSP, not U+202F | `,` U+002C | no |
| `indian` | `,` U+002C | `.` U+002E | **yes** |
| `auto` | detected; default `comma_dot` | | |

**Grouping** (locale-format.ts:112-118): ≤3 digits ungrouped. Non-Indian inserts the
group separator every 3 digits from the right. Indian groups the **last 3** digits,
then the remaining head every **2** digits: `12345678` → `1,23,45,678`.

**`formatNumber`** (locale-format.ts:170-184): non-finite ⇒ `"0"`;
`maxFrac = maximumFractionDigits ?? 2`;
`minFrac = min(minimumFractionDigits ?? 0, maxFrac)`; sign extracted, magnitude
rendered with `toFixed(maxFrac)`, then trailing zeros trimmed **down to `minFrac`**;
the decimal mark is emitted only if a fractional part survives.

**Compact tiers** (locale-format.ts:189-217): `1e12 → "T"`, `1e9 → "B"`,
`1e6 → "M"`, `1e3 → "K"`; fraction digits are 2 when the scaled value is <10, 1
when <100, else 0. Below 1,000 there is no suffix and `maxFrac` is 4 for |v|<1,
else 2. Suffixes are Latin and deliberately **not** localised.

**Token-amount ladder** (locale-format.ts:228-240): `0` or non-finite ⇒ `"0"`;
`compact && |v| ≥ 1e6` ⇒ compact form; `|v| ≥ 1000` ⇒ exactly 2 decimals;
`|v| ≥ 1` ⇒ up to 4; `|v| < 1` ⇒ up to 6, or up to 4 in compact mode **unless**
that renders `"0"`, in which case 6 (so dust never reads as zero).

**`parseLocaleNumber`** (locale-format.ts:144-154), in this order: `trim`; map
Arabic-Indic U+0660–U+0669 and Extended Arabic-Indic U+06F0–U+06F9 to ASCII; if the
preset's group separator is whitespace, strip **every** whitespace kind (so NBSP and
U+202F pasted from another app parse); else remove the group separator literally;
finally map the preset's decimal mark to `.`.

## Currency

### CLDR fraction digits

Today `formatFiat` (`src/services/currency.ts:108-111`) is a binary 2-or-0 rule
driven by a hand-maintained 17-code set. Against CLDR it is wrong for **21 of the
137** codes in `src/services/currency-catalog.ts` (measured against node 22.22.3 /
ICU 78.2):

| Class | Digits | Codes |
|---|---|---|
| Three-decimal | **3** | `KWD`, `BHD`, `OMR`, `JOD`, `TND`, `LYD` — **6 codes**, all rendered with 2 today |
| Zero-decimal, already correct | 0 | `JPY`, `KRW`, `IDR`, `ISK`, `HUF`, `VND`, `CLP`, `PYG`, `RWF`, `UGX`, `XOF`, `XAF`, `XPF`, `GNF`, `VUV` — 15 codes, in the app's set |
| Zero-decimal, **missing today** | 0 | `LBP`, `PKR`, `MMK`, `LAK`, `COP`, `ALL`, `AFN`, `IRR`, `IQD`, `SYP`, `YER`, `SOS`, `BIF`, `MGA`, `SLL` — **15 codes**, rendered with 2 today |
| Everything else | 2 | the remaining 101 catalog codes |

6 + 15 = **21**, which is the figure the spec quotes. `KMF` and `DJF` also appear in
the app's `ZERO_DECIMAL_CODES` but are **not** in the 137-code catalog, so they are
unreachable and do not count either way.

**Both zero-decimal rows are size 15, and FR-020's phrase "0 for the 15
zero-decimal codes" is ambiguous between them.** The full CLDR zero-decimal set
within the catalog is **30** codes, not 15. This document treats the implementable
rule as *all 30* — anything narrower reintroduces the defect for whichever half is
excluded — and reads FR-020's "15" as naming the 15 codes SC-010 counts as
*corrected*. A reviewer should confirm that reading before the currency table is
generated.

Orthogonal to CLDR, the app also drops minor units above a
`DECIMAL_DROP_THRESHOLD` of 100,000 (`currency.ts:96-101`). That is a deliberate
product rule, not a CLDR rule, and survives the port as an explicit option.

### Symbol placement and spacing, for the 15 shipped locales

Measured with `Intl.NumberFormat(lng, {style:'currency', currency:'EUR',
currencyDisplay:'narrowSymbol'})` on node 22.22.3 / ICU 78.2. `formatFiat` today is
unconditionally `symbol + number` with **no** separator.

| Class | Locales | Pattern | Example (€, 1234.5) |
|---|---|---|---|
| Symbol before, no space | en, zh, zh-TW, zh-HK, ja, ko, id, tr, es-MX | `¤#,##0.00` | `€1,234.50` |
| Symbol before, **U+00A0** | pt-BR | `¤ #,##0.00` | `€ 1.234,50` |
| Symbol after, **U+00A0** | vi, fr, de, ru, it | `#,##0.00 ¤` | `1.234,50 €` |

The count is **6 locales** where today's `symbol + number` is structurally wrong,
exactly as the spec says. The membership measured here differs from the spec's
parenthetical (`vi, ru, fr, it, de, es-MX`) in one entry: **es-MX places the symbol
*before* the amount with no space and is already correct; pt-BR places it before
with U+00A0 and is wrong.** Everything else matches. Recorded, not silently
propagated — a reviewer should correct the spec's list or this table, not both.

Two spacing rules, both required:

1. **The literal space in the pattern** is always U+00A0 (NBSP), never U+0020 and
   never U+202F, for every locale above.
2. **CLDR `currencySpacing`** additionally inserts U+00A0 between an **alphabetic**
   symbol and the digits, even in the no-space class. This is live for Vela,
   because `currency-catalog.ts` supplies alphabetic symbols (`CHF`, `PLN`, `RM`,
   `zł`, `kr`, `Rp`, and any code with no glyph). Measured: `en` + `KWD` →
   `KWD\u{00A0}1,234.500`, while `en` + `JPY` → `¥1,235` with no space.

**U+202F appears only as a *group* separator**, in `fr` (and, in ICU, nowhere else
among the 15). Under FR-020 grouping stays with the user's preset, so U+202F is not
emitted by Vela's formatter — `space_comma` uses U+0020. `ru`'s CLDR group
separator is U+00A0, also not emitted for the same reason. ICU also renders `it` at
four digits *ungrouped* (`1234,50`), where Vela's preset system groups
unconditionally above 3 digits — another reason grouping is not taken from CLDR.

Text direction is `Ltr` for all 15 shipped locales; `Dir::Rtl` exists for FR-023 and
is not reachable from the current locale set.

## CoreError extension

Five new variants on the existing flat `CoreError` (`rust/crates/vela-core/src/error.rs`).
Feature 001's conventions apply unchanged: **variants classify, messages carry
detail**, and `code()` is the stable machine-readable string the conformance
vectors match on.

| Variant | `Display` | `code()` | Raised by |
|---|---|---|---|
| `I18nEmptyKeyList(String)` | `t() called with an empty key list: {0}` | `I18nEmptyKeyList` | **Oracle throw 1** — `t([])`. i18next dereferences `keys[keys.length - 1]` with no length check and throws a raw `TypeError: Cannot read properties of undefined (reading 'includes')` |
| `I18nInvalidCount(String)` | `count is not convertible to a number: {0}` | `I18nInvalidCount` | **Oracle throw 2** — `t(key, {count: 5n})`. `Intl.PluralRules.select(5n)` throws `TypeError: Cannot convert a BigInt value to a number`. Message quotes the offending value |
| `I18nUnsupportedOption(String)` | `i18n option is not supported by the Rust surface: {0}` | `I18nUnsupportedOption` | The object-returning options, deliberately not ported: `returnObjects: true` on a branch, `returnDetails: true`, and `joinArrays` with an array `defaultValue`. Message names the option |
| `I18nCatalogParse(String)` | `i18n catalog JSON is malformed: {0}` | `I18nCatalogParse` | FR-015 — a runtime catalog that is not an object of string leaves, or whose value blob exceeds the u16 offset ceiling |
| `I18nCatalogUnavailable(String)` | `i18n catalog is not available for locale: {0}` | `I18nCatalogUnavailable` | FR-014/FR-016 — a locale that is neither compiled in nor supplied as JSON. **Not reachable from `t()`**, which falls through to `en` |

**Resolved during specification review**: `I18nEmptyKeyList(String)` carries a
`String` so the enum stays uniform — every existing `CoreError` variant carries one,
and a payload-free variant would be the only exception in the FFI contract. The
payload is caller-supplied context (the call site or namespace), not invented detail.
The `code()` string is `"I18nEmptyKeyList"` either way, so no conformance vector
depends on the choice.

Likewise the malformed-catalog variant is named **`I18nCatalogParse`**, not
`I18nCatalogMalformed`, to match the existing `AbiParse` / `Eip712Parse` naming in
`error.rs`.

**What is *not* an error.** i18next returns a diagnostic *string* for a branch
node, and the port returns that string byte for byte:

```
key '<key> (<language>)' returned an object instead of string.
```

Source: i18next.js:618. `<language>` is `this.language` — the **active** language,
not the language the value was found in. `t('common')` under `en` yields
`key 'common (en)' returned an object instead of string.` The same string is
returned for `returnObjects: false` (the default), for `joinArrays` on an object,
and for an object or array `defaultValue`.

**Foreign mapping** follows the established pattern: the uniffi shell needs the five
mirror variants added to its `CoreError` enum and `From` impl; the wasm shell needs
nothing, because it serialises `e.code()` generically.

## Invariants (asserted by tests, not just documented)

1. **No input panics.** Any `(key, locale, options)` triple — malformed keys, empty
   key arrays, unbalanced braces, cyclic nesting, non-UTF-8-representable option
   values, `NaN`/`±Inf` counts — returns `Ok` or `Err`, never unwinds (FR-026).
2. **Output is stable.** The same input resolved twice returns byte-identical
   output, in any order, from any registry state reachable by load/release.
3. **`PATHS` is strictly sorted, deduplicated, and has exactly 1,205 entries**; no
   entry is both a leaf and a branch in any locale.
4. **Offsets are monotone and in-bounds**: `off[0] == 0`, `off[i] <= off[i+1]`,
   `off[N_PATHS] == blob.len()`, and every `off[i]..off[i+1]` slice lands on a UTF-8
   boundary.
5. **`present` and `branch` are disjoint** for every path id in every catalog: a
   path is a value, a branch, or absent — never two of those.
6. **Every value blob is under 65,536 bytes**, so u16 offsets cannot overflow
   (headroom today: 7,835 bytes on `ru`, the largest).
7. **Residency never exceeds active + `en`.** After any sequence of
   load/release/change-language operations, at most two catalogs are reachable, and
   `en` is always one of them (SC-005, SC-009).
8. **Lookup allocates zero times**; a full resolution with a plural and two
   interpolations allocates **at most twice** (SC-007).
9. **The engine holds no per-key state.** Resolving unboundedly many distinct keys
   leaves resident memory flat (FR-024, SC-009).
10. **Every corpus key in every locale resolves to a non-empty string** or to a
    documented fallback (`en`, or the branch diagnostic) — 17,115 cross-product
    cases, none of which returns a non-string or throws in the oracle (D4).
11. **The candidate list has at most 6 entries** and is consumed strictly
    last-in-first-out.
12. **`plural_suffixes(lng)` equals the CLDR cardinal category set** for each of the
    15 locales, in CLDR order, and every one of the 29 reachable (locale, category)
    pairs is produced by some count.
13. **MODE A and MODE B differ on exactly the recorded set** — 75 of 825 plural
    cases — so an unexpected divergence is a regression, not noise.
14. **Round-tripping the corpus through the generator is byte-identical**: no
    trimming, no reordering, no re-encoding, no normalisation (FR-009, SC-006).
